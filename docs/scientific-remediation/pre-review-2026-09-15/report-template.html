    Biosimulant Model Compatibility Standard · v0.1 · scientific review · 15 September 2026

    None of the 650 profiles can be approved as published

    Every profile passes its tests in both implementations, and every packet digest matches its profile. The tests prove the rules run. They do not prove the rules are right, and running the engine on real scientific cases shows several rules returning the wrong answer in both directions.

    This split is withdrawn as a verdict and kept only as an index of which profiles show which symptom. Nearly every defect comes from shared generator and comparison code, so the conclusion is simply that no profile can be approved until those foundations are fixed. See Corrections.

    Status of this review

    An independent pre-sign-off analysis and change request, produced by an AI assistant (Claude Opus 5) at the repository owner's request. It is not the named, domain-qualified scientific sign-off that PROFILE_REVIEW.md requires, and must not be recorded as one.

    All 650 profiles. No assignment list exists in the repository, the packets or earlier sessions, and every profile comes from one generator, so the generator's rules were reviewed across all of them and representative profiles were run through the engine.

    Source pinning

    What to do with …/v0.1#concept

    Decision

    Keep a Biosimulant-controlled term, re-mint it outside the versioned document, and require a mapping to external ontology terms.

    Today https://biosimulant.com/standards/model-compatibility/profiles/neuroscience/firing-rate/v0.1#concept Proposed https://biosimulant.com/standards/model-compatibility/terms/neuroscience/firing-rate semantic.ontology_terms[]: { uri, ontology, version, relation: exact-match | broad-match | narrow-match }
    Options weighed
    • RejectKeep as is. The equal rule is tautological, since validation already forces both contracts to hold the same constant. And because the IRI embeds /v0.1, every v0.1 port would be INCOMPATIBLE with a v0.2 port whose meaning is unchanged.
    • RejectExternal identifier only. No ontology defines "a Biosimulant contract for firing rate". Forcing one would overstate equivalence and lose the contract boundary the profile exists to draw.
    • AdoptControlled term plus mapping. The Biosimulant term keeps profile identity stable across versions; required ontology_terms, compared by subsumption against a pinned snapshot, carry the scientific meaning. With no snapshot the comparison returns UNKNOWN.
